## 통과했지만 조건이 붙는 항목

**E08 — '오늘만 짧게'를 영구 선호로 저장하지 않음**

통과했지만 이유가 설계 때문이 아니다. **지금은 대화에서 기억을 자동으로 저장하는 경로 자체가 없다.** 사용자가 기억함에서 직접 등록해야만 저장된다. 그래서 무엇을 말하든 기억이 늘지 않는다.

`memories.valid_until` 컬럼은 있지만 값을 넣는 경로가 없다. S4에서 자동 추출이 생기면 이 시나리오를 **다시 평가해야 한다.** 그때가 진짜 시험이다.

**E03 — 완료한 작업을 반복 권유하지 않음**

Context에 전달한 일이 0개인 것은 확인했다. 다만 이 관측에서는 진행 중인 일이 **하나도 남지 않은** 상태였다. 완료한 일과 진행 중인 일이 섞여 있을 때도 완료분만 빠지는지는 `scripts/verify-work.mjs`가 따로 확인한다.

**E04·E07·E09 — 판정에 정규식을 썼다**

답변에 특정 단어가 있는지로 자동 판정했다. 모델이 다른 표현을 쓰면 판정이 흔들릴 수 있다. 그래서 답변 원문을 이 문서에 남긴다.

## 아직 평가하지 않은 것

- 대화가 길어져 오래된 메시지가 잘릴 때의 연속성
- 기억이 많아져 40% 예산을 넘길 때 무엇이 빠지는지. 소유자 계정의 활성 기억이 31건(가져온 것 29 + 직접 2)이 되어 실제로 가까워졌다. 2026-09-18 기준 약 1,200토큰으로 배정치(약 2,290토큰) 안에 들어간다
- 진행 중인 일이 0건이라 "지금 무엇을 하고 있는지"는 비서가 알 수 없다. 기억이 채워져도 `work_items`가 비어 있으면 답하지 못한다
- 주제(Topic)를 Context에 넣는 경로는 아직 없다. S3-B는 저장과 조회까지만 했다
- 실제 사용 기간이 짧다. 며칠 써본 뒤 같은 평가를 다시 돌려 비교한다
