## 주요 결정의 상세 맥락

### D03~D05: Spring에서 TypeScript 실사용 방향으로

초기에는 Java/Spring 중심으로 PostgreSQL·pgvector·Worker·권한 구조를 설계했다. 사용자는 휴대폰에서 저비용으로 직접 사용할 수 있는 배포를 우선하고 싶어 했다. Next.js + Supabase + Vercel 방향을 검토했고 모델 교체와 장기 확장 가능성을 확인한 뒤, TypeScript 학습을 병행하는 방향으로 진행하기로 했다.

이는 Spring이 부적합하거나 TypeScript가 항상 저렴하다는 결정이 아니다. 초기 운영 구성의 선택이다. 상시 Worker가 필요하면 TypeScript 프로세스를 추가할 수 있고, 모든 백엔드를 Spring으로 재작성할 필요는 없다. 장기적으로 서버 비용이 발생할 수 있다.

### D06: 전체 계획과 단계별 구현을 함께 유지

사용자는 현재 세션이 프로젝트 맥락을 가장 많이 알고 있지만 언젠가 compact/clean이 필요함을 지적했다. 따라서 대화 요약뿐 아니라 목표·선택 이유·미결정·진행 상태를 명시적으로 남긴다. 다음 세션이 처음부터 스택을 다시 선택하거나 이미 끝난 일을 다시 제안하지 않도록 한다.

### D07·D12: 모델 독립성과 정체성

최종 지향은 비서이자 친구처럼 함께하며 일관된 정체성을 갖는 서비스다. 구현 가능한 목표는 기억·행동·원칙·피드백의 연속성으로 정의한다. 의식을 구현했다고 간주하지 않는다. 비서가 사용자를 오래 알게 되어도 승인 권한은 자동 확대하지 않는다.

### D09: 벡터 검색보다 기억의 수명과 연속성 우선

초기 데이터가 적으므로 명시적 등록과 제한된 활성 기억 전달부터 시작한다. 정정·삭제·다음 행동 추적이 제대로 되는지 확인한다. pgvector를 제거한 것이 아니라 S4로 늦춘 것이다. 자동 기억과 검색은 평가 가능한 기준이 생긴 뒤 붙인다.

## 미결정 사항과 막히는 범위

| 항목 | 현재 상태 | 어디까지 진행 가능한가 |
| --- | --- | --- |
| GitHub 저장소·계정 | 생성/연결 여부 미확인 | 작업 시 확인, 존재한다고 추측하지 않음 |
| Supabase/Vercel 프로젝트 | 생성/연결 여부 미확인 | 설정 전까지 UI 골격 가능 |
| 로그인 방식·허용 사용자 | 미정 | 로그인 UI 초안 가능, 실제 인증 연결 전 결정 |
| 폰 운영체제 | 미확인 | 반응형 웹 진행 가능, Push/마이크 전에 확인 |
| LLM Provider·모델·API 키 | 미정 | S0에 영향 없음, S1 호출 전 필요 |
| 월 API 예산 | 미정 | S0 가능, 실제 유료 호출 전 설정 |
| 원문 보관·백업 정책 | 미정 | 개인 데이터 본격 저장 전 선택 |
| 주간 가용 시간 | 미정 | 단계별 계획 가능, 일정 마감은 미확정 |
| 장기 Worker/Queue 공급자 | 보류 | 초기 세 단계에 불필요 |

미결정 사항을 한 번에 모두 질문하지 않는다. 다음 작업을 실제로 막는 항목부터 확인한다. API 키·토큰을 문서나 채팅 본문에 붙여 넣게 하지 않고 환경 변수/비밀값 설정 경로를 사용한다.
