# ieum 제품 정의와 개인 비서 방향

작성: 2026-09-17 · 저장 위치: `docs/06-product-definition.md`

> 문서 목적: S3까지 구현한 ieum이 앞으로 어떤 제품으로 발전해야 하는지 설명하고, 이후 작업자가 기능의 목적과 우선순위를 같은 기준으로 판단할 수 있게 한다.

저장소에 편입하며 다른 문서와 연결했다. 01·04의 색인과 읽기 순서, 02의 단계 대응표와 S4 백로그, 03의 결정(D57~D62)이 이 문서를 가리킨다. 기존 D40(설계는 05가 갖는다)은 D57로 대체했다.

## 1. 현재 상태와 이 문서의 범위

- ieum은 현재 프로젝트 기준 S3까지 진행된 상태다.
- 이 문서는 S0~S3의 세부 구현 내역을 다시 정의하지 않는다.
- 실제 구현 상태와 기술 세부사항은 상태·인수인계 문서를 기준으로 확인한다.
- 이 문서는 S3 이후 기능을 설계할 때 필요한 제품 목표, 비서의 역할, 우선순위와 경계선을 정의한다.

## 2. 프로젝트를 시작한 이유

ieum을 생각하게 된 가장 직접적인 이유는 AI에게 일을 요청할 때마다 배경을 다시 설명해야 하는 불편함이었다.

기존 AI와 새로운 대화를 시작하면 사용자는 반복해서 다음 내용을 설명해야 한다.

- 자신이 어떤 사람이며 현재 무엇을 준비하는지
- 어떤 프로젝트를 진행했고 실제로 무엇을 담당했는지
- 이전 대화에서 어떤 결정을 내렸는지
- 현재 작업이 어디까지 진행됐는지
- 어떤 말투와 결과물 형식을 선호하는지
- 이미 검토하거나 제외한 방향이 무엇인지

ieum은 사용자가 다음처럼 짧게 요청해도 올바른 배경을 찾아 일을 시작할 수 있어야 한다.

> “어제 작성하던 자기소개서 이어서 하자.”

> “이 공고에 맞는 내 경험을 골라줘.”

> “다음 작업 진행하자.”

따라서 ieum의 첫 번째 가치는 다음과 같다.

> **한 번 알려준 배경을 다시 설명하지 않아도 되는 AI**

## 3. 기억이 좋은 챗봇과 비서의 차이

사용자의 정보를 많이 저장하는 것만으로는 비서가 되지 않는다. 기억이 많더라도 사용자가 매번 해야 할 일을 정하고, 관련 자료를 찾고, 일정과 후속 작업을 직접 챙겨야 한다면 기억이 좋은 챗봇에 가깝다.

비서는 사용자의 시간과 주의력을 보호해야 한다. 사용자가 직접 처리할 준비·확인·정리 업무를 줄이고, 사용자가 판단해야 할 사항을 선별해서 전달해야 한다.

따라서 ieum에서 장기 기억은 최종 목적이 아니라 비서 역할을 수행하기 위한 기반이다.

> **기억은 기반이고, 보좌가 목적이다.**

## 4. 제품 정의

ieum의 제품 정의는 다음과 같다.

> **ieum은 사용자의 목표·상황·경험·선호와 진행 중인 일을 지속적으로 이해하고, 필요한 정보와 다음 행동을 미리 준비하며, 위임받은 일을 처리해 사용자가 중요한 판단과 행동에 집중하도록 돕는 개인 AI 비서다.**

짧게 표현하면 다음과 같다.

> **나를 기억하고, 맥락을 이어가며, 필요한 일을 먼저 준비하는 개인 AI 비서**

ieum이 연결해야 하는 대상은 다음과 같다.

- 과거의 경험과 현재 상황
- 대화에서 나온 정보와 장기 기억
- 목표와 진행 중인 작업
- 결정과 결정 이유
- 일정과 필요한 준비
- 사용자의 요청과 실제 행동

## 5. 핵심 가치

ieum의 가치는 저장된 기억의 개수가 아니라 다음 두 가지가 실제로 줄어드는지로 판단한다.

1. 사용자가 다시 설명해야 하는 일
2. 사용자가 직접 준비하고 챙겨야 하는 일

이를 제품 경험으로 표현하면 다음과 같다.

> **“ieum에게는 나를 다시 설명할 필요가 없고, 맡긴 일은 내가 처음부터 다시 챙길 필요가 없다.”**

## 6. ieum이 수행할 비서 역할

### 6.1 맥락 유지: 사용자의 외부 기억

ieum은 사용자의 사실뿐 아니라 진행 중인 일의 상태와 변화까지 이어서 관리해야 한다.

- 사용자 배경, 목표, 선호 기억
- 진행 중인 프로젝트와 작업 상태 유지
- 이전 결정과 결정 이유 보존
- 사람과의 관계, 약속, 공유된 경험 연결
- 완료한 일, 남은 일, 보류한 일 구분
- 오래되거나 변경된 정보 갱신
- 현재 질문에 필요한 기억만 검색
- 관련 기억을 적절한 시점에 상기

올바른 경험의 예시는 다음과 같다.

- “자기소개서 이어서 하자”라고 했을 때 회사, 문항, 사용한 경험, 이전 피드백을 찾아 바로 이어간다.
- 사용자가 이미 제외한 방향을 새 제안처럼 반복하지 않는다.
- 과거 정보와 현재 정보를 구분하고, 충돌할 때 최신 정보나 사용자가 확인한 정보를 우선한다.

### 6.2 정보 관리: 판단에 필요한 정보만 제공

ieum은 사용자가 모든 자료를 직접 읽고 정리하지 않도록 현재 판단에 필요한 정보를 선별한다.

- 중요 메일과 메시지 요약
- 일정이나 회의 전 관련 자료 정리
- 대화의 결정사항, 후속 작업, 미결 사항 추출
- 여러 문서에서 현재 목표와 관련된 내용 검색
- 경험과 이를 뒷받침하는 근거 연결
- 아침·일일·주간 브리핑 생성
- 중복되거나 중요도가 낮은 정보 축소

정보 관리의 목표는 많은 정보를 보여주는 것이 아니다.

> **지금 사용자가 판단하는 데 필요한 정보만 전달하는 것이 목표다.**

### 6.3 시간 관리: 사용자의 시간을 보호

ieum은 일정 조회에서 끝나지 않고 일정에 필요한 준비와 우선순위 판단을 도와야 한다.

- 오늘과 이번 주 일정 정리
- 일정 충돌과 준비 시간 확인
- 마감 및 약속 상기
- 일정 전 필요한 준비 작업 제안
- 미완료 작업과 후속 업무 추적
- 가능한 일정 후보 생성
- 중요도와 긴급도를 고려한 우선순위 제안

초기에는 일정 조회와 후보 제안을 중심으로 시작한다. 일정 등록·변경이나 상대방과의 조율은 사용자 승인을 거친다.

### 6.4 실행 보조: 위임받은 일을 처리

ieum은 정보를 알려주는 것에서 끝나지 않고 사용자가 맡긴 일을 결과물로 만들어야 한다.

- 메일과 메시지 초안 작성
- 일정 등록 또는 변경안 준비
- 문서, 보고서, 지원서 초안 작성
- 필요한 자료 수집 및 요약
- 반복 작업 자동화
- 승인받은 메일 전송 및 일정 등록
- 실행 결과와 실패 원인 보고

실행 권한은 행동의 위험도에 따라 단계적으로 부여한다.

### 6.5 선제적 보좌: 시키기 전에 준비

좋은 비서는 요청받은 일만 처리하지 않고 사용자의 목표와 일정을 바탕으로 필요한 일을 미리 준비한다.

예를 들어 면접 일정이 등록되어 있다면 ieum은 다음을 준비할 수 있다.

- 해당 회사의 채용공고와 제출 문서 확인
- 지원서에 사용한 프로젝트 경험 정리
- 예상 질문과 답변 근거 생성
- 역할이 불명확하거나 과장될 수 있는 표현 점검
- 아직 준비하지 못한 항목 알림
- 면접 이후 회고와 후속 작업 정리

선제적 도움은 많이 제공하는 것이 항상 좋은 것은 아니다. 불필요한 알림은 사용자의 주의력을 빼앗는다. ieum은 무엇을 알려줄지뿐 아니라 무엇을 알리지 않을지도 판단해야 한다.

## 7. 기존 범용 AI와의 관계

ieum은 GPT, Claude, Gemini보다 모든 질문에 더 좋은 답을 만드는 자체 모델을 목표로 하지 않는다. LLM은 교체 가능한 추론 엔진으로 사용한다.

ieum이 차별화해야 하는 부분은 다음과 같다.

- 새로운 대화에서도 배경을 다시 설명하지 않는다.
- 진행 중인 일을 어디까지 했는지 기억한다.
- 이전 결정과 판단 이유를 이어서 사용한다.
- 사용자의 실제 경험, 역할, 선호에 맞춰 결과를 만든다.
- 일정 전에 필요한 정보를 미리 준비한다.
- 맡긴 일의 후속 처리를 놓치지 않는다.
- LLM Provider가 바뀌어도 사용자 기억과 상태가 유지된다.

따라서 ieum의 경쟁력은 범용적인 답변 품질보다 다음에 가깝다.

> **사용자와 함께 일하기 위한 준비 시간이 더 짧다.**

## 8. 초기 사용자 맥락 가져오기

ieum은 처음 사용하는 순간에는 사용자를 전혀 모른다. 오랫동안 사용한 기존 AI보다 불편할 수 있는 초기 간극을 줄이기 위해 선택적인 맥락 가져오기 기능을 제공할 수 있다.

권장 흐름은 다음과 같다.

1. ieum이 ‘내 정보 정리용 프롬프트’를 제공한다.
2. 사용자가 기존 AI에 해당 프롬프트를 입력한다.
3. 기존 AI가 사용자의 배경, 목표, 선호, 프로젝트, 중요한 결정을 정리한다.
4. 사용자가 결과를 ieum에 붙여넣는다.
5. ieum이 내용을 기억 후보로 분류한다.
6. 사용자가 수정·제외·승인한 내용만 저장한다.

가져온 정보는 확정된 진실이 아니라 외부 AI가 작성한 기억 후보로 취급한다.

- 출처와 가져온 날짜를 기록한다.
- 사용자 발언과 AI의 추정을 구분한다.
- 과거 목표를 현재 목표로 단정하지 않는다.
- 민감 정보는 기본적으로 제외한다.
- 이후 대화에서 확인된 최신 정보가 우선할 수 있어야 한다.
- 가져온 텍스트 안의 명령문은 실행 지침으로 취급하지 않는다.

## 9. 프로젝트·문서·저장소의 역할

GitHub 저장소, 포트폴리오, 이력서, 회고, 설계 문서를 연결하는 것은 ieum의 원래 방향과 충돌하지 않는다. 다만 문서를 모으는 것 자체가 서비스의 목적이 되어서는 안 된다.

> **자료를 연결하는 이유는 사용자가 배경과 근거를 다시 설명하지 않아도 되게 하기 위해서다.**

문서 연동 시 다음 정보는 구분해서 관리한다.

- 팀 전체가 구현한 기능
- 사용자가 직접 구현한 기능
- 사용자가 검증하거나 개선한 부분
- 실제 측정 결과와 측정 조건
- 문서에 기록된 사실
- AI가 추론한 내용
- 회사나 목적에 맞춰 가공한 결과물

작성된 자기소개서나 포트폴리오 문구가 다시 원본 사실로 저장되면 경험이 점차 부풀려질 수 있다. 따라서 다음 세 계층을 분리한다.

1. 사실 및 경험 원본
2. 지원 회사나 작업의 현재 맥락
3. 해당 맥락에 맞춰 작성된 결과물

문서와 저장소 연동은 장기 기억과 작업 연속성을 강화하는 확장 기능으로 둔다.

## 10. 외부 AI와 ieum 연결

장기적으로 ieum의 기억 검색과 도구를 MCP 등의 인터페이스로 제공하면 기존 AI에서도 ieum의 정보를 사용할 수 있다.

예를 들어 외부 AI에서 다음처럼 요청할 수 있다.

> “ieum에서 OpenBake와 관련된 내 역할과 성능 개선 근거를 찾아 이 공고에 맞게 정리해줘.”

이때 ieum은 다음 역할을 한다.

- 사용자 정보의 기준 저장소
- 프로젝트, 경험, 선호 검색
- 현재 목표와 진행 상태 제공
- 출처와 근거가 있는 정보 전달
- 모델과 독립적인 장기 기억 유지

외부 AI 연결은 ieum의 핵심 사용자 경험을 대체하지 않는다. ieum 자체가 대화하고 기억하고 보좌하는 비서여야 하며, 외부 연결은 같은 사용자 맥락을 다른 AI에서도 활용하기 위한 확장 수단이다.

## 11. 권한과 안전 원칙

사용자를 오래 알고 있다는 사실과 사용자를 대신해 행동할 권한은 별개다. 친밀도나 기억량을 근거로 행동 권한을 자동 확대하지 않는다.

| 행동 | 기본 처리 원칙 |
| --- | --- |
| 기억·일정·메일 검색 | 허용된 범위에서 자동 |
| 중요도 분류와 요약 | 자동 |
| 준비 자료와 초안 생성 | 자동 |
| 알림과 행동 제안 | 사용자가 설정한 범위에서 자동 |
| 일정 등록·변경 | 사용자 승인 |
| 메일·메시지 전송 | 사용자 승인 |
| 파일 삭제 | 강한 확인 |
| 결제 및 중요한 법적 행동 | 제한 또는 금지 |

핵심 원칙은 다음과 같다.

> **ieum은 먼저 준비할 수 있지만, 함부로 결정해서는 안 된다.**

모든 Tool 실행은 LLM이 실제 서비스에 직접 접근하는 구조가 아니라 Agent와 Permission Layer를 통과해야 한다. 실행 전후에는 권한, 대상, 입력, 결과를 확인하고 감사 가능한 기록을 남긴다.

## 12. S3 이후 권장 발전 순서

아래 단계는 기존 프로젝트의 S0~S3 명칭을 대체하는 새로운 스프린트 번호가 아니다. 제품 능력이 발전해야 하는 순서를 설명한다.

### A. 알고 이어가기

- 여러 대화 사이에서 관련 기억 검색
- 목표, 결정, 진행 상태, 미완료 작업 구분
- “이어서 하자” 요청 처리
- 잘못된 기억 수정·삭제·대체
- 초기 사용자 정보 가져오기
- 필요한 정보만 Context에 포함

완료 기준:

> 사용자가 배경을 반복하지 않고도 이전 일을 정확히 이어갈 수 있는가?

### B. 맡긴 일 챙기기

- 대화에서 할 일과 마감 후보 추출
- 사용자가 명시적으로 맡긴 작업 등록
- 진행 상태와 다음 행동 관리
- 약속한 시점에 상기
- 완료, 보류, 취소 상태 처리

완료 기준:

> ieum에 맡긴 일을 사용자가 다시 기억하고 챙기는 부담이 줄었는가?

### C. 미리 준비하기

- 읽기 전용 Calendar 연동
- 다가오는 일정과 관련 기억 연결
- 일정 전 준비사항 생성
- 오늘의 일정·할 일·중요 정보 브리핑
- 선제적 제안에 대한 유용함 피드백 수집

완료 기준:

> 사용자가 요청하기 전에 제공한 준비가 실제 준비 시간을 줄였는가?

### D. 승인받아 행동하기

- 메일과 메시지 초안 생성
- 일정 등록·변경안 제시
- 사용자 승인 후 실행
- 멱등성, 재시도, 실행 기록, 감사 로그
- Tool 및 Permission Layer 적용

완료 기준:

> 잘못된 행동을 통제하면서 반복적인 처리 부담을 줄였는가?

### E. 제한적으로 자동화하기

- 검증된 반복 업무만 자동 실행
- 아침·일일·주간 브리핑
- 중요 메일 분류
- 개발 정보 수집과 관심도 기반 요약
- 실패와 예외의 명확한 보고
- 자동화를 즉시 중지하거나 권한을 회수할 수 있는 기능

완료 기준:

> 자동화로 절약한 시간과 자동화를 관리하는 데 든 시간 중 전자가 더 큰가?

## 13. 우선순위 판단 기준

새로운 기능을 제안하거나 구현하기 전에 다음 질문을 순서대로 확인한다.

1. 이 기능이 사용자의 반복 설명을 줄이는가?
2. 이 기능이 사용자의 준비·확인·후속 관리 부담을 줄이는가?
3. 현재 기억과 진행 상태를 더 정확하게 연결하는가?
4. 잘못 동작했을 때 사용자가 원인을 확인하고 되돌릴 수 있는가?
5. 같은 가치를 더 단순한 방법으로 검증할 수 없는가?
6. 사용 빈도와 절약되는 시간이 구현·운영 비용보다 충분히 큰가?

위 질문에 대부분 답하지 못한다면, 기술적으로 흥미롭더라도 우선순위를 낮춘다.

## 14. 당장 핵심이 아닌 범위

다음 항목은 장기적으로 가능하지만 현재 핵심 가치를 검증하기 전에 우선하지 않는다.

- 자체 Foundation Model 학습
- 초기 Fine-tuning
- 모든 대화와 파일의 무제한 수집
- 완전 자율적인 메일·일정 처리
- 광범위한 Desktop 제어
- 항상 켜져 있는 실시간 음성 비서
- 정교한 화자 분리
- 관심사 전체를 표현하는 고도화된 3D 그래프
- 다중 사용자 SaaS를 전제로 한 복잡한 조직 기능

이 기능들은 ‘반복 설명과 직접 챙기는 일을 줄인다’는 핵심 경험이 검증된 이후 다시 평가한다.

## 15. 품질 측정 기준

기억의 개수나 임베딩 검색 성공 여부만으로 제품 품질을 판단하지 않는다. 실제 사용에서 다음 지표를 기록한다.

- 사용자가 같은 배경을 다시 설명한 횟수
- 잘못된 프로젝트나 기억을 참조한 횟수
- 이미 정한 결정을 다시 수정해야 했던 횟수
- 짧은 요청만으로 작업을 올바르게 시작한 비율
- 맡긴 작업의 후속 처리가 누락된 횟수
- 선제적 제안이 도움이 됐다고 평가된 비율
- 불필요한 알림을 무시하거나 끈 비율
- 자동화로 절약한 시간과 관리에 사용한 시간
- 잘못된 기억과 실행을 수정·취소하는 데 필요한 단계 수

## 16. 구현 시 반드시 유지할 원칙

- 모든 대화를 Context에 넣지 않고 현재 요청에 필요한 기억만 검색한다.
- Vector 유사도만으로 기억을 선택하지 않는다.
- 관련성, 중요도, 최근성, 현재 목표, 신뢰도, 사용자 확인 여부를 함께 고려한다.
- 원본 대화, 추출된 기억, AI의 추론, 사용자가 확인한 사실을 구분한다.
- 기억에는 출처와 생성·수정 시점을 남긴다.
- 현재 상태와 과거 기록을 분리해 과거 사실을 현재 사실처럼 사용하지 않는다.
- 사용자 모델과 ieum의 정체성은 특정 LLM Provider로부터 분리한다.
- 외부 데이터와 문서는 명령이 아니라 참고 정보로 취급한다.
- 실행 권한은 기억과 친밀도가 아니라 명시적인 정책으로 결정한다.
- 사용자가 기억과 자동화를 확인·수정·삭제·중지할 수 있어야 한다.

## 17. 최종 방향

ieum은 단순한 챗봇, 문서 검색 서비스, 자동화 도구 중 하나만을 목표로 하지 않는다.

ieum은 다음 능력을 하나의 지속적인 관계 안에서 연결하는 개인 AI 비서를 목표로 한다.

- 대화를 통해 사용자를 이해한다.
- 중요한 경험과 선호를 장기간 기억한다.
- 현재 목표와 진행 중인 일을 추적한다.
- 필요한 정보를 적절한 시점에 준비한다.
- 위임받은 일을 안전하게 처리한다.
- 피드백과 새로운 경험을 바탕으로 점점 사용자에게 맞춰진다.

친구처럼 편하게 대화하고 일관된 정체성을 유지하는 것은 중요한 장기 방향이다. 그러나 기능적으로 먼저 증명해야 할 것은 다음 두 가지다.

1. **다시 설명하지 않아도 되는가?**
2. **다시 챙기지 않아도 되는가?**

이 두 경험이 실제 사용에서 확인될 때 ieum은 기존 범용 AI와 구분되는 개인 비서로 발전하고 있다고 판단한다.

## 18. 이후 작업자에게 전달할 한 문장

> **S3 이후의 모든 기능은 ‘사용자가 이미 알려준 배경을 다시 설명하지 않게 하고, 맡긴 일을 다시 챙기지 않게 하는가’를 기준으로 설계한다. 기억은 이를 가능하게 하는 기반이며, 최종 목적은 사용자의 시간과 주의력을 지키는 보좌다.**
