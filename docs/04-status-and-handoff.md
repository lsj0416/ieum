# ieum — 현재 상태와 새 세션 인계

최종 갱신: 2026-09-18 · 계획 버전: 0.1 · 현재 단계: **S3 완료 · 연속성 평가 1회 수행 · S4-0 완료** · 다음 작업 S4-A (대화에서 기억 자동 추출)

## 1. 가장 먼저 알아야 할 것

이 프로젝트(`ieum`, 이음)는 사용자의 기억과 진행 맥락을 이어가는 개인 AI 비서다. 최종 지향은 시간이 지날수록 사용자에게 맞춰지고, 일관된 정체성을 유지하며, 필요한 순간 도움을 주는 경험이다.

현재 구현 방향은 **Next.js + TypeScript + Supabase + Vercel + AI SDK**다. 사용자는 Java/Spring 경험이 더 많고 TypeScript를 배우며 진행한다. 초기 Spring 설계는 대안으로 보존하지만 이번 구현을 Spring으로 전환해야 한다고 전제하지 않는다.

첫 실사용 목표는 **다음 날 새 대화에서 마지막 결정과 다음 행동을 이어서 안내하는 모바일 웹**이었다. S0~S3으로 달성했고 연속성 평가 E01~E10을 1회 통과했다.

다만 실사용에서 다음 벽이 드러났다. **비서가 사용자를 모르고 이전 대화를 찾지 못한다.** 기억을 손으로 등록해야만 알고, Context는 현재 대화만 읽기 때문이다. 문서 06의 A단계가 아직 끝나지 않았다.

S4-0으로 쓰던 AI의 정리를 옮겨 오는 길을 열었다(2026-09-18). 손으로 한 줄씩 넣지 않아도 기억을 채울 수 있다. 다만 **대화에서 저절로 쌓이지는 않고**(S4-A) **다른 대화를 찾지도 못한다**(S4-B).

S3 이후의 방향은 `06-product-definition.md`가 정한다. 핵심은 두 문장이다. **다시 설명하지 않아도 되는가, 다시 챙기지 않아도 되는가.** 기억은 그 기반이고 목적은 보좌다.

대화·주제·지도의 상세 설계는 `05-conversations-topics-and-map.md`에 있다. 대화를 여러 개로 나누되 주제(Topic)가 여러 대화에 걸쳐 모이므로 대화 분리가 맥락 단절을 뜻하지 않는다.

## 4. 다음 작업

**S4-A: 대화에서 기억 자동 추출.**

S4-0으로 기억을 한 번에 채우는 길은 열렸다(2026-09-18). 남은 구멍은 둘이다.

| 없는 것 | 현재 |
| --- | --- |
| 대화에서 기억을 자동으로 저장하는 경로 | 직접 등록하거나 가져온 것만 전달한다. 대화가 쌓여도 기억은 늘지 않는다 |
| 여러 대화에 걸친 검색 | Context는 현재 대화의 최근 메시지만 읽는다(`eq("conversation_id", …)`) |

| ID | 작업 | 이유 |
| --- | --- | --- |
| **S4-A** | 대화에서 기억 자동 추출 | 사용자가 손으로 등록하지 않아도 쌓이게 한다 |
| S4-B | 여러 대화에 걸친 검색 | "지난번에 뭐 했지"에 답한다 |

**S4-0이 S4-A에 물려주는 것이 있다.** 후보(`memory_candidates`)와 승인 흐름, 모델이 댄 근거를 원문과 대조하는 검사, 민감 정보 기본 제외, 사용자 발언과 AI 추정의 구분(`attribution` → `memories.source`)이 이미 있다. 자동 추출은 후보를 만드는 입구만 대화로 바꾸면 된다. 다만 **대화에서 뽑은 후보를 매번 사용자에게 물어볼 수는 없다.** 언제 묻고 언제 조용히 넘길지는 S4-A에서 정한다.

**S2에서 만들어두고 아직 쓰지 않는 것이 둘 있다.** `memories.valid_until`은 컬럼만 있고 값을 넣는 경로가 없다. 기한 있는 선호(E08)가 이것을 요구하며, 자동 추출이 생기면 이 시나리오를 다시 평가해야 한다. `memory_evidence.source_message_id`는 대화 중 기억 등록 경로가 없어 여전히 비어 있다. 가져온 기억의 근거는 `source_kind = IMPORT`로 남는다.

**수동 입력의 근거(quote)는 지금도 거의 쓰이지 않는다.** 저장되고 기억함에서 펼쳐볼 수만 있고 Context에는 들어가지 않는다. 가져오기에서는 이 자리가 실제로 쓰인다(원문 대조). 수동 입력에까지 강제하는 것이 맞는지는 S4-A에서 함께 정리한다.

## 6. 잃으면 안 되는 맥락

- 낮은 비용으로 직접 휴대폰에서 사용하기 위해 스택을 바꿨다. 언어의 우열을 정한 것이 아니다.
- TypeScript로 Worker와 독립 백엔드까지 확장할 수 있다. Vercel의 실행 제약을 TypeScript의 한계로 해석하지 않는다.
- 모델보다 기억·진행 상태·권한의 독립성이 핵심이다.
- 장기 기억, 진행 중인 일, 현재 상태, 비서 정체성을 구분한다.
- 관측하지 못한 사용자 행동을 추측해 현재 상태로 확정하지 않는다.
- ‘자아’의 구현 목표는 일관된 정체성과 경험의 반영이다. 의식의 달성이나 감정을 사실로 주장하지 않는다.
- 친밀함은 실행 승인이 아니다. 외부 도구 연동부터 권한 검사를 적용한다.
- 정정·삭제는 원문 재노출, 요약, 진행 중 추출과 함께 검토한다.
- 사용자는 문서로 전체 맥락을 보존한 뒤 단계별로 개발하기를 원한다.
