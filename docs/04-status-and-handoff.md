# ieum — 현재 상태와 새 세션 인계

최종 갱신: 2026-09-16 · 계획 버전: 0.1 · 현재 단계: **S3 완료** · 다음 작업 S3-03 연속성 평가 또는 S4-A 자동 발견

## 1. 가장 먼저 알아야 할 것

이 프로젝트(`ieum`, 이음)는 사용자의 기억과 진행 맥락을 이어가는 개인 AI 비서다. 최종 지향은 시간이 지날수록 사용자에게 맞춰지고, 일관된 정체성을 유지하며, 필요한 순간 도움을 주는 경험이다.

현재 구현 방향은 **Next.js + TypeScript + Supabase + Vercel + AI SDK**다. 사용자는 Java/Spring 경험이 더 많고 TypeScript를 배우며 진행한다. 초기 Spring 설계는 대안으로 보존하지만 이번 구현을 Spring으로 전환해야 한다고 전제하지 않는다.

첫 실사용 목표는 **다음 날 새 대화에서 마지막 결정과 다음 행동을 이어서 안내하는 모바일 웹**이다. S0~S2로 로그인·대화·기억까지 왔고, 남은 조각이 S3의 작업 연속성이다.

S3 이후의 방향은 `05-conversations-topics-and-map.md`가 정한다. 대화를 여러 개로 나누되 주제(Topic)가 여러 대화에 걸쳐 모이므로, 대화 분리가 맥락 단절을 뜻하지 않는다.

**S3-A: 대화 목록과 새 대화.**

S0~S2는 완료했고 배포해 사용 중이다. 다음 방향은 `05-conversations-topics-and-map.md`가 정한다.

지금 화면에는 대화가 하나뿐이다. `/chat`이 가장 최근 대화를 열고 거기에 계속 덧붙인다. 대화 목록도 새 대화 버튼도 없다. S1-04에서 "여러 작업을 다루는 S3에서 필요해진다"고 미뤘던 것을 여기서 만든다.

`conversations` 테이블은 이미 복수 대화를 담을 수 있다. 새 저장 체계를 만들지 않는다.

S0~S3을 구현했다. 남은 것은 연속성 평가(S3-03)와 S4 이후다. 미래 기능의 상세 스키마를 지금 전부 만들지 않는다. 초기에는 명시 기억과 현재 작업을 제한된 Context로 전달하고, 데이터와 검색 필요가 늘 때 pgvector를 붙인다.

## 6. 잃으면 안 되는 맥락

- 낮은 비용으로 직접 휴대폰에서 사용하기 위해 스택을 바꿨다. 언어의 우열을 정한 것이 아니다.
- TypeScript로 Worker와 독립 백엔드까지 확장할 수 있다. Vercel의 실행 제약을 TypeScript의 한계로 해석하지 않는다.
- 모델보다 기억·진행 상태·권한의 독립성이 핵심이다.
- 장기 기억, 진행 중인 일, 현재 상태, 비서 정체성을 구분한다.
- 관측하지 못한 사용자 행동을 추측해 현재 상태로 확정하지 않는다.
- ‘자아’의 구현 목표는 일관된 정체성과 경험의 반영이다. 의식의 달성이나 감정을 사실로 주장하지 않는다.
- 친밀함은 실행 승인이 아니다. 외부 도구 연동부터 권한 검사를 적용한다.
- 정정·삭제는 원문 재노출, 요약, 진행 중 추출과 함께 검토한다.
- 사용자는 문서로 전체 맥락을 보존한 뒤 단계별로 개발하기를 원한다.
