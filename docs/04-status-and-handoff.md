# ieum — 현재 상태와 새 세션 인계

최종 갱신: 2026-09-16 · 계획 버전: 0.1 · 현재 단계: S0 진행 중 (S0-01~05 완료)

## 1. 가장 먼저 알아야 할 것

이 프로젝트(`ieum`, 이음)는 사용자의 기억과 진행 맥락을 이어가는 개인 AI 비서다. 최종 지향은 시간이 지날수록 사용자에게 맞춰지고, 일관된 정체성을 유지하며, 필요한 순간 도움을 주는 경험이다.

현재 구현 방향은 **Next.js + TypeScript + Supabase + Vercel + AI SDK**다. 사용자는 Java/Spring 경험이 더 많고 TypeScript를 배우며 진행한다. 초기 Spring 설계는 대안으로 보존하지만 이번 구현을 Spring으로 전환해야 한다고 전제하지 않는다.

첫 실사용 목표는 **다음 날 새 대화에서 마지막 결정과 다음 행동을 이어서 안내하는 모바일 웹**이다.

## 4. 다음 작업

**S0-06: RLS와 서버 접근 검사를 확인한다.**

S0-01~05는 완료했다. 완료 조건은 허용되지 않은 계정과 비인증 요청의 데이터 접근 거절이다.

현재는 업무 테이블이 하나도 없어 RLS를 걸 대상이 없다. 실제 테이블은 S1의 conversations/messages에서 처음 생긴다. 따라서 S0-06은 다음 중 하나를 고른다.

1. 지금 최소 테이블 하나로 RLS 동작과 거절 경로를 확인한다.
2. S0-07 배포를 먼저 하고, RLS는 S1-01 스키마 작업과 함께 검증한다.

어느 쪽이든 **소유자 본인 계정으로 실제 로그인한 기록이 아직 없다.** 배포 전에 로컬에서 한 번 로그인해 `last_sign_in_at`을 확인하는 것이 남아 있다.

첫 체크포인트는 본인 계정으로 휴대폰에서 로그인 가능한 배포다. 이 단계에는 모델 호출·벡터 검색·외부 서비스 연동을 넣지 않는다. 계정 연결이 막혀도 가능한 UI/설정 예시/검증 준비는 진행하고, 막힌 설정만 구체적으로 설명한다.

이번 문서 작업만으로 배포·새 계정 생성·유료 결제·외부 메시지 전송이 허가되었다고 해석하지 않는다. 이후 실제 구현·배포 요청 범위와 해당 환경 권한을 따른다.

## 5. 전체 로드맵 요약

S0 배포/인증 → S1 대화 저장 → S2 명시 기억 → S3 작업 연속성 → S4 자동 기억/검색 → S5 피드백 개인화 → S6 선제 브리핑 → S7 승인된 실행 → S8 음성/Companion.

S0~S3 먼저 실사용한다. 미래 기능의 상세 스키마를 지금 전부 만들지 않는다. 초기에는 명시 기억과 현재 작업을 제한된 Context로 전달하고, 데이터와 검색 필요가 늘 때 pgvector를 붙인다.

## 6. 잃으면 안 되는 맥락

- 낮은 비용으로 직접 휴대폰에서 사용하기 위해 스택을 바꿨다. 언어의 우열을 정한 것이 아니다.
- TypeScript로 Worker와 독립 백엔드까지 확장할 수 있다. Vercel의 실행 제약을 TypeScript의 한계로 해석하지 않는다.
- 모델보다 기억·진행 상태·권한의 독립성이 핵심이다.
- 장기 기억, 진행 중인 일, 현재 상태, 비서 정체성을 구분한다.
- 관측하지 못한 사용자 행동을 추측해 현재 상태로 확정하지 않는다.
- ‘자아’의 구현 목표는 일관된 정체성과 경험의 반영이다. 의식의 달성이나 감정을 사실로 주장하지 않는다.
- 친밀함은 실행 승인이 아니다. 외부 도구 연동부터 권한 검사를 적용한다.
- 정정·삭제는 원문 재노출, 요약, 진행 중 추출과 함께 검토한다.
- 사용자는 문서로 전체 맥락을 보존한 뒤 단계별로 개발하기를 원한다.
